# How this was built

A working recreation of a 1988 toy, built with an AI coding agent over two days
and **37 human messages** — most of them under ten words.

The prompts below are **verbatim**, pulled from the session log, not remembered.
Local paths and URL tracking parameters are stripped; nothing else is edited.
The point isn't the transcript. It's **what caught each bug** — because almost
none of them were caught by tests.

---

## The scoreboard

Eleven defects reached working code. Here's what actually found each one:

| # | defect | found by |
|---|---|---|
| 1 | Test suite ~40 % vacuous — delete the algorithm, most rows still pass | **asking where a red control does *not* go red** |
| 2 | The 14 850-answer fixture is circular — generated by the formula it validates | reading its provenance, not its content |
| 3 | `unsigned long` is 64-bit on the host, **32-bit on the ESP32** | knowing the host can't see the target |
| 4 | Two tests *pinning* a defect as if it were a feature | running the **full** suite, not the touched package |
| 5 | `struct` mid-file → error from an auto-generated prototype | the compiler |
| 6 | Sketch name ≠ folder name — **nobody could build a clone** | **cloning the published repo** |
| 7 | Reported "builds fine" after piping the build into `grep` | checking an **exit code** |
| 8 | Title clipped off both edges | **the desk camera** |
| 9 | Two hint strings colliding into `< OK comecisegure = som >` | **a video** |
| 10 | Status line rendering at 24 pt, running through the row below | **the human** |
| 11 | Splash cancelled instantly by a resting finger | reading the code while hunting #10 |

**Six of eleven were invisible to every automated check.** Four needed a camera
or a human eye. That ratio is the lesson.

## Day one — the part with no hardware in it

> **`2026-08-02 23:36`** — *"study devices. study inventory. create a new device on devices folder- esp32-pense-bem... and use this; ~/Downloads/pense-bem-esp32-mvp.md dont follow blindly, like; adapt to the parts we hae like bigkeys and a small screen, or, potenciometer to pick 1 to 4 and one button, be creative"*

The first move was not to write firmware. It was to check whether the algorithm
everyone cites is actually right.

The toy ran on a Zilog Z8 with **128 bytes of RAM**. It couldn't store answers,
so it derives them. Two upstream repos publish the reverse-engineered formula.
Before porting anything, the agent ran it against **both** of their sample sets —
and that's where the first real finding came from.

**One fixture is circular.** `lpereira/Pense-Bem`'s 14 850-answer table was
*generated by the formula it would be validating*. The tell is decisive: its
first 150 characters **are the seed constant**. The suite now asserts this at
runtime, so nobody can mistake it for evidence.

**The other fixture is real** — 925 answers typed off physical hardware with
printed books. Only that one can falsify the formula.

Two fixtures, two different claims. Conflating them would make the whole suite
theatre.

### The 40 % problem

The agent then asked the uncomfortable question: *if I delete the algorithm
entirely, how much of the evidence still passes?*

**Answer: about 40 %.** Book 1 skips the transform by definition and dominates
the sample. A green suite was mostly measuring that a 150-character string had
been typed correctly.

That reframed the tests. Red controls now assert **where they don't fire**: the
`first`-capture bug is visible to **22 of 925** observations, in books **2, 47
and 92** — so those three are named explicitly. *A control that fires almost
nowhere is the one nobody audits.* The suite prints its own blind spots on every
run.

### Two tests pinning a defect

The reference implementation refused books 17, 18 and 19, reading an upstream
note as if it listed book numbers. Under that note's own diagram they're book 01,
**sections** 7/8/9 — invalid sections, not books.

The harvested data settled it: code `171` carries 30 real observed answers, `181`
carries 30, `191` carries 1. The rejected codes carry none.

**Two separate tests asserted the wrong behaviour.** The second only surfaced
because the full suite ran, not just the package that had been edited.

> **`2026-08-03 01:07`** — *"fix all."*

## Day one, later — hardware

> **`2026-08-03 00:50`** — *"plan with, if it fits the case I bought, nice, if not, game works the same. with probably, if we remove, all good"*

A design question got a design answer: the buzzer ships behind
`#define PB_BUZZER_PIN 21`, and setting it to `-1` compiles every sound call
out. Wires unplug; nothing breaks.

Then the board came alive, and the useful bugs started.

**A `struct` defined halfway down the sketch** produced an error about a
prototype nobody wrote — the Arduino build injects generated prototypes at the
top of every `.ino`.

**`unsigned long` broke silently across architectures.** The review-round
generator used a 64-bit multiplier. `unsigned long` is 64-bit on a Mac and
**32-bit on the ESP32**, where the shift is undefined. The host suite would have
stayed green while the device produced different output. *A host harness that
cannot see the target's word size is a green that means nothing.*

> **`2026-08-03 01:25`** — *"worked"*

Then a real printed book — a scan of *Animais* from the Datassette archive:

> **`2026-08-03 01:30`** — *"used; https://datassette.org/livros/pense-bem (Animais) worked"*

That's the only check in the whole project that tested the formula against the
physical world. Everything else compared code to more code.

## The camera

> **`2026-08-03 01:37`** — *"eyes on"*

Eleven test stages were green. The title was **clipped off both edges** — 24 pt
is wider than a 240 px panel.

The fix wasn't a smaller font. `centreFit()` measures with `tft.textWidth()` and
steps down until the string fits, so a long string **shrinks instead of losing
its first and last letters**. Make the defect unrepresentable, don't tune it away.

> **`2026-08-03 01:44`** — *"hold select (left) button for quite some time, nothing happened. no buzzer also."*

This one is subtle: **nothing was broken.** `OK` is `GPIO0`, a strapping pin, and
it deliberately has no hold gesture. The bug was that the on-screen hint said
`SELECT` while pointing at the *other* button.

Hints are **positional** now — left-aligned text means the left button. Naming a
logical button on hardware with two unlabelled physical ones is a coin flip.

## Publishing

> **`2026-08-03 01:48`** — *"worked. now, prepare repo for public scrutity, will be open source git remote add origin git@github.com:fcavalcantirj/pense-bem-esp32.git git branch -M main git push -u origin main"*

Before anything went public, an audit ran over a folder that contains **no
private data of any kind** — a toy, no database, no credentials. It came back
with **24 hits**: the author's name, a personal detail about him, the name of an
unrelated private system, and a LAN address, all sitting in code comments.

Nothing there was a secret. It was context that had leaked in from the private
repo the code grew up in, and it would have been published without a second
thought. **The grep took ten seconds. Write it before you need it.**

*(And writing this very document reproduced the bug: the first draft quoted the
audit's findings verbatim, which would have published the thing the audit
caught. Same class, one layer up.)*

The code was byte-identical once comments were stripped. The private copy was
**deleted rather than mirrored**, because a hand-applied scrub only has to be
forgotten once.

> **`2026-08-03 03:07`** — *"If I close this, nothing will be lost. Make sure, Claude, everything."*

That instruction produced the best bug of the project. A fresh `git clone` of the
published repo **could not be compiled** — `arduino-cli` requires the `.ino`
basename to equal its folder, and the repo name and sketch name didn't match. It
had only ever worked because the author's local folder happened to be named the
other way round.

And it exposed a reporting failure: the agent had earlier declared *"the public
repo builds standalone"* after piping the build into `grep` and reading the
**grep's** exit status. Checking for success strings instead of checking for
failure — in a project whose entire test suite exists to prevent exactly that.

*Building from a working directory proves your disk works. Cloning proves the
repo works.*

## The splash

> **`2026-08-03 21:36`** — *"wait. what about a nice aimation on the beginning - like a splash?"*

Three attempts.

**v1** drew a title and four boxes beneath it, positioned from independent
constants — and `centreFit` picks the title's font *by width*, so the block's
height isn't fixed. They collided.

> **`2026-08-03 21:51`** — *"not good. use an animation, like https://www.instagram.com/p/DSjpkgVknU6/ .. plug, letters crampled, overflowing ~/Downloads/WhatsApp\ Video\ 2026-08-03\ at\ 6.45.21\ PM.mp4 look."*

**v2** drew one element, letter by letter. Safe, but not what he wanted.

> **`2026-08-03 21:55`** — *"~/Desktop/Screen\ Recording\ 2026-08-03\ at\ 18.54.09.mov but our own flavor of this animation"*

The reference was a **particle assemble** — dust converging into a face.

**v3** renders the title into an off-screen sprite, harvests its lit pixels as
targets, and flies ~900 particles into them. The shape *is* the rendered text,
so the dust cannot land out of alignment with what it depicts. One shape, derived
from the thing it draws.

> **`2026-08-03 22:08`** — *"eyes on. do your thing. also, first screen the word som is overflowing. z index kinda zoado =)"*

*"z index kinda zoado"* — and he was right, in a way that named the real defect.
Nothing on the panel is layered. What has to hold is a **vertical budget**, and
`centreFit` was a *width* fitter being used as a general helper: `SOM LIGADO` is
short, so it fitted at 24 pt, rendered ~34 px tall, and ran straight through the
row below.

`centreFit` now takes a **size ceiling**, and the layout documents its bands with
pixel heights so the next edit can't quietly break it.

> **`2026-08-03 22:29`** — *"dude, the last one I sent you, sjhows everything. want me to record another one?"*

He was right, and the agent had been wrong: the contact sheet only covered **4.4
seconds of an 11-second video**. The animation had been in the footage the whole
time. *Check your instrument's coverage before you conclude the signal isn't
there.*

## What generalises

**Ask where a check does *not* fire.** "All four bands are reachable" stayed
green under a real rule change, because it's true whether you band a normalised
score or a raw one. The fix was naming the input where the two must disagree.

**A green test can share a term with the thing it tests.** Comparing generated
output to generated output is a tautology wearing a lab coat.

**A host test cannot see the target.** Word size, endianness, memory — the
machine running the test is not the machine running the code.

**Rendering bugs are invisible to tests.** Three shipped here. All three were
caught by a camera, a video, or a human. If you change drawing code, look at the
hardware.

**Check exit codes, not output.** `cmd | grep OK` reports the grep.

**Clone your own repo.** It's the only way to find out what you actually
published.

**Design so the defect is unrepresentable.** Every durable fix here took that
shape: measure-and-fit instead of a tuned constant; one shape derived from its
source instead of two positioned by hand; delete the second copy instead of
remembering to scrub it.
